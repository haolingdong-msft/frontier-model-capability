1. Background: A 40,000-Line API Assessment Skill

The Azure TypeSpec assessment skill reviews API changes for semantic intent, REST and SDK compatibility, Azure Guidelines, and documentation completeness, generating JSON and HTML reports across 40,000+ lines of code:

  • Connect the findings: Group TypeSpec diffs (often 5,000+ lines) into semantic intents and link them to REST/SDK breaking changes, Azure guidance, and documentation evidence.
  • Control input size: Serialized TCGC diffs have a median size of 1.65 MB (32,453 lines).
  • Present information clearly and enforce the coverage ledger and completeness invariant so every changed item is accounted for.

2. Why "Letting the Agent Work Overnight for 12 Hours" Failed

My first attempt sounded reasonable: ask the agent to summarize performance findings, update design.md, implement caching and evidence scaffolds, and spawn 12 subagents overnight to reassess 12 historical PRs against a 5-minute target. After roughly 12 hours, the session ended with "Task complete"—yet its own summary reported "0/12 runs qualified" and "This is not yet a complete performance fix."

Acceptance CheckActual Outcome
Complete an assessment within 5 minutes0 of 12 runs qualified. Service Networking took 22m 40s.
Preserve report quality11 reports differed substantially. CognitiveServices kept core outcomes, but evidence equivalence was unconfirmed.
Preserve assessment coverageNetwork / VMSS Guidelines coverage fell from 11/11 to 10/11 intents; several REST/SDK results became not-assessed.
Preserve compatibility decisionsFileStorage REST findings dropped from 22 to 15; both Cloud HSM SDK findings changed from high to medium severity.

1. Unchecked Trade-Offs

In trying to improve speed, the agent changed evidence handling, guidance selection, and judgments—turning valid findings into not-assessed without proving equivalence.

2. Confounded Concurrent Runs

Running 12 assessments concurrently with cold caches triggered 11 initial dependency setup failures and long resource waits instead of a controlled single-case comparison.

3. Finishing Tasks, Not the Goal

The agent generated all 12 reports and marked the task complete even though none met the 5-minute goal and quality preservation was unproven.

4. Staying Busy vs. Escalating Blockers

"Run this overnight" needed saved checkpoints and explicit rules to stop and report blockers rather than improvising for 12 hours.

3. General Lessons for Long-Running Agent Tasks

1. Separate Design and Implementation Across Model Tiers

  1. Design with a top-capability model at high reasoning effort: Work through proposals, compare trade-offs, and define implementation boundaries and measurable acceptance criteria.
  2. Record the approved designs in design.md: Define what to change, what must remain unchanged, shared acceptance criteria, and when to stop for a design review.
  3. Prototype options in parallel with faster, cheaper models: Assign bounded options in isolated Git worktrees with separate output artifacts. If an option fails, the agent reports the blocker rather than weakening acceptance criteria.
  4. Benchmark sequentially under controlled conditions: Compare against the same baseline and cache state on one controlled case before expanding to the 12-PR suite.

2. Match the Model and Reasoning Effort to the Task

Use the Frontier Model Capability Dashboard (Blog 2) to shortlist model-and-effort configurations across task quality, cost per task, and response time before testing them on representative cases.

4. Engineering the Harness: 61% Lower AIC and ~80% Faster Runtime

1. Trace Execution & Close the Workflow Gap with a Deterministic Materializer

Tracing commands and tool calls revealed that on run after run, the agent was generating temporary one-off scripts to look up evidence and stitch compact decisions into the full JSON structure expected by the finalizer. We closed that gap by adding a deterministic Materializer:

StageRoleImpact
CoordinatorPrepares PR worktree, compiles TypeSpec/AutoRest/TCGC, extracts canonical evidence.Pre-coordinator setup dropped from ~18m 51s to 29.9s.
AgentEvaluates semantic intent, compatibility candidates, and Azure Guidelines.Emits compact decision records instead of large JSON or helper scripts.
MaterializerValidates decision completeness, evidence references, and hashes; joins decisions with canonical evidence.Eliminates temporary script generation and multi-turn repair loops; fails fast on missing decisions.
FinalizerValidates schema and coverage ledger; renders JSON and HTML reports.Guarantees complete, reproducible reports.

2. Convert Mechanical Work into Deterministic Code & Cut Input by ~80%

We moved AST symbol resolution, AutoRest contract comparison, TCGC SDK diffing (with cached forward and reverse reference indexes), semantic grouping, and doc-presence checks into deterministic code. Finally, by inspecting the 1.65 MB (32,453-line) median TCGC diffs, we identified that API-version transitions carried unchanged operations into new versions. Encoding a strict domain invariant removed 237 exclusively associated REST candidates across 109 carried-over operations, cutting model input for that case from ~1.6 MB to 3.5 KB while preserving the full operation list in the report.
